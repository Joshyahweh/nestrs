NestRS **1.7** adds Axum-native crates for reliability, outbound integrations, durable workflows, and LLM agents. Enable them with umbrella features on `nestrs`, or depend on the crates directly. This page is the hub; each package has an ecosystem guide and an API reference.

<Note>
**Explicit exceptions (not silent gaps):** Express/Fastify adapters (ADR-0001 Axum-only), Nest Observe SaaS / Mau deploy (open OTel instead), and `nestrs-drizzle` until upstream publishes. See [roadmap](/guides/reliability#roadmap).
</Note>

## Install

```toml
[dependencies]
nestrs = { version = "1.7.0", features = [
  "resilience", "idempotency", "outbox", "locks",
  "mail", "webhooks", "workflows", "ai",
] }
```

Or depend on individual crates (`nestrs-resilience = "1.7.0"`, …) for a thinner graph.

## Foundation features

These live in core `nestrs` / `nestrs-core` / `nestrs-openapi` — no extra crate:

| Capability | NestRS API |
|------------|------------|
| Stable machine-readable error codes | `HttpException::with_error_code("WEAK_PASSWORD")` → JSON `errorCode` |
| Schema + validation for DTOs | `NestrsSchema` + `SchemaValidationPipe` (`Validate` + `JsonSchema`) |
| OpenAPI DTO `$ref` auto-link | `OpenApiRouteSpec::{request_body_schema, response_schema}` |
| Route conflict / shadow diagnostics | `RouteConflictPolicy` on `NestApplication` |
| Richer `ExecutionContext` | `get_class` / `get_handler` / name accessors |
| Controller-level pipes | `controller_pipes = …` on `#[routes]` |
| Span attrs for handlers | OTel attrs `nestrs.controller` / `nestrs.handler` |

```rust
use nestrs::prelude::*;

#[get("/signup")]
async fn signup() -> Result<Json<Value>, HttpException> {
    Err(BadRequestException::new("Password is too weak").with_error_code("WEAK_PASSWORD"))
}
```

Response body:

```json
{
  "statusCode": 400,
  "message": "Password is too weak",
  "error": "Bad Request",
  "errorCode": "WEAK_PASSWORD"
}
```

## Wire modules like other NestRS dynamic modules

Every reliability crate follows the same pattern as `CacheModule` / `ThrottlerModule`:

1. Call `FooModule::register(options)` → `DynamicModule`
2. Put it in `#[module(imports = [...])]`
3. Inject the exported service (`Arc<FooService>`) into an `#[injectable]` provider

```rust
use nestrs::prelude::*;
use std::sync::Arc;

#[injectable]
struct OrdersService {
    resilience: Arc<nestrs::resilience::ResilienceService>,
    mail: Arc<nestrs::mail::MailService>,
}

#[module(
    imports = [
        nestrs::resilience::ResilienceModule::register(
            nestrs::resilience::ResilienceOptions::default()
        ),
        nestrs::mail::MailModule::register(
            nestrs::mail::MailOptions::default()
        ),
    ],
    providers = [OrdersService],
    controllers = [OrdersController],
)]
struct AppModule;
```

<Warning>
`DynamicModule` only **exports** listed `TypeId`s. These modules export their services; if you build a custom dynamic module, pass `vec![TypeId::of::<YourService>()]` to `from_parts` or importers cannot inject it.
</Warning>
